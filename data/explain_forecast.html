미래소요 예측 — 알고리즘 설명

1. 학습 데이터

현재 사용 중인 데이터(기본 내장 가상데이터, 또는 ③ 탭에서 생성·불러온 데이터)의 청구일자(REQ_DATE)로 학습합니다. 데이터 기간의 모든 평일 × 출발 보급기지 × 수령지역 조합마다 그날 청구 건수를 세어 학습표를 만듭니다(청구가 없는 날은 0건으로 포함).

2. 입력 특징

  • 요일(월~금) — 8차원 임베딩
  • 출발 보급기지, 수령지역 — 각각 8차원 임베딩
  • 계절 — 연중 일수의 sin·cos (12월 말과 1월 초가 이어지도록 원형 표현)
  • 분기말 여부 — 3·6·9·12월 20일 이후면 1

3. 모델 (MLP)

임베딩 24차원 + 달력 특징 3개 = 27차원 → 은닉층 64(ReLU, 배치정규화, 드롭아웃 10%) → 32(ReLU) → 출력 1(그날 건수). 손실은 평균제곱오차, 최적화는 Adam(학습률 0.005, 배치 64, 15 epoch). NumPy로 직접 구현해 PyTorch 없이 동작합니다.

4. 재현성과 재학습

  • 초기값·데이터 섞기에 고정 시드(42)를 써서 같은 데이터는 항상 같은 결과가 나옵니다.
  • 데이터를 바꾸면(③ 탭 '이 데이터를 ①·②에 사용') 자동으로 다시 학습합니다(약 1초). 데이터 내용의 해시값별로 가중치를 저장해 같은 데이터는 다시 학습하지 않습니다.

5. 시계열 모델 4종 비교 (실제 사용)

날짜별 총 청구 건수는 아래 네 모델로 예측하고 비교합니다. 모두 NumPy로 직접 구현했고(작은 자동미분 엔진 포함) PyTorch 등 외부 딥러닝 라이브러리는 쓰지 않습니다.

  • 입력: 과거 20 평일(약 4주)의 일별 총 건수(평균으로 정규화) + 각 날의 요일(원-핫)·계절 sin·cos·분기말, 그리고 예측 대상일의 날짜 특징. 주말은 청구가 없어 시퀀스에서 뺍니다.
  • 출력: 대상일 하루의 총 건수. 향후 N일은 예측값을 다음 입력으로 이어 붙이는 재귀 방식.
  • 검증: 데이터의 마지막 40 평일을 학습에서 빼고, 1일 앞 예측의 MAE·RMSE(건/일)를 계산해 비교표에 표시합니다. MAE가 가장 작은 모델을 ★최우수로 표시하고 기본 선택합니다. 실제 예측은 전체 기간으로 다시 학습한 모델을 씁니다.
  • 학습: 전체 배치 Adam(학습률 0.01, 300회), 고정 시드 42. 네 모델 합계 십여 초, 데이터 해시별로 캐시합니다.
  • 지역·보급기지별 배분: 선택 모델이 낸 날짜별 총 건수를 위 2~3의 임베딩 MLP가 예측한 보급기지×수령지역 비율로 나눕니다.
모델구현 내용장점단점
MLP20일 시퀀스를 펼쳐 은닉층 32(ReLU) → 대상일 특징과 결합 → 16 → 1가장 단순·빠름시간 순서를 구조적으로 쓰지 않음
RNN(GRU)은닉 16의 GRU가 하루씩 상태를 갱신(갱신·리셋 게이트), 마지막 상태로 예측순서·누적 패턴 반영순차 계산이라 느리고 긴 시퀀스 학습이 어려움
1D CNN커널 5(1주) 합성곱 → 커널 3 합성곱 → 시간 평균주간 주기 같은 국소 패턴에 강함, 빠름먼 과거 반영에 한계
트랜스포머(소형)입력·위치 임베딩(16) → 1헤드 셀프어텐션 1층 + 피드포워드(잔차) → 시간 평균모든 날 사이 관계를 한 번에 계산데이터가 적으면 과적합·불안정

6. 향후 N일 예측 절차

  1. 시작일부터 N일의 날짜를 만듭니다. 토·일은 청구 없음(0건).
  2. 선택한 모델로 평일의 총 건수를 예측하고, 임베딩 MLP의 비율로 보급기지×수령지역에 나눕니다(음수는 0).
  3. 날짜별 합계(그래프), 수령지역·보급기지별 합계(표, 지도 원 크기)로 보여 줍니다. 그래프의 회색 선은 현재 데이터의 최근 실적입니다.

7. 전통 시계열 방법 (본 프로그램에서는 사용하지 않음)

방법원리장점단점
이동평균 / 지수평활최근 값들의 (가중)평균으로 다음 값을 추정. 홀트-윈터스는 추세·계절 추가매우 단순·빠름, 해석 쉬움범주 정보(지역·기지)를 함께 쓰기 어렵고 급변에 늦음
ARIMA과거 값(자기회귀)과 과거 오차(이동평균)의 선형 결합, 차분으로 추세 제거통계적 근거·신뢰구간 제공계열마다 따로 모델 필요, 비선형 관계 약함

8. 이렇게 설계한 이유

  • 데이터 규모: 1년치(평일 약 260일) 수준이라 모델을 작게(은닉 16~32) 유지했습니다. 데이터가 적을수록 단순한 모델이 이길 수 있어 네 모델을 같은 조건에서 비교합니다.
  • 가벼움: NumPy만으로 학습·예측해 실행파일이 작고 내부망 PC에서도 동작합니다.
  • 웹 확장: 같은 계산 모듈의 결과(JSON)를 웹 화면에서 그대로 보여 줍니다.
